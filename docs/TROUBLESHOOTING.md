# Troubleshooting AULA WIN 60 HE MAX

[User guide](USER_GUIDE.md) · [Open the configurator](https://primebuild-pc.github.io/aula-win60he-tool/) · [Report a bug](https://github.com/PrimeBuild-pc/aula-win60he-tool/issues/new?template=bug_report.yml)

## The Connect button is unavailable

Use desktop Chrome or Edge and an HTTPS URL, or localhost during development. Firefox and Safari do not provide the WebHID API used by Studio. An embedded browser may also lack device access: open the same URL directly in Chrome or Edge.

## No keyboard appears in the device picker

1. Check the model and USB IDs. Studio targets **AULA WIN 60 HE MAX `1CA2:1902`**, vendor interface `FFA0:0001`.
2. Use a data-capable USB cable and a direct computer port.
3. Close other AULA driver tabs or applications that may hold the interface.
4. Reconnect the cable and try Connect again.

On Linux, check access to the matching HID interface. Use a narrowly scoped permission rule for the actual device rather than running the browser as root. A keyboard continuing to type does not establish access to its separate vendor configuration interface.

## Connection stops during profile or polling changes

Some device changes can interrupt USB communication. Reconnect and read the settings again before applying another change. The welcome screen returning is intentional: settings must be read from the newly connected device. Keep only one configurator connection open.

## RGB preview changes but the keyboard does not

The preview is a **local draft**. Press **Apply lighting**, then use **Read again** and compare the device values with the physical result.

- Brightness is **0–4**; 0 is dark. Choose a visible level.
- Palette entries are **0–6**, with **7** reserved for rainbow.
- Per-key colors require custom mode. Paint the selected keys, then apply.
- Dynamic animations are generated by firmware. The preview shows colors, not the actual animated pattern.
- If another driver changes the keyboard, read settings again before editing a new draft.

Version 0.3.0 corrected incompatible brightness/speed ranges, palette indices and custom-mode write ordering. If you see the old interface, reload with Ctrl+Shift+R and check the version link in the workspace. A pending GitHub Pages deployment may mean the public site still serves the previous version.

If the app reports a readback failure, keep the exact message and observed result. Do not describe a successful readback as optical proof that an LED lit up.

## WASD or A/D type arrows or stop typing

Use **Set Fn arrows** in Overview to restore WASD letters on the base layer. Check whether SOCD is enabled: this firmware ignores the Fn layer on SOCD keys. Use **Fn + Right Alt / Right Ctrl** for left/right while A/D SOCD is active.

Reset or remove an advanced action from the affected key if it replaced normal behavior. Do not remap away the physical Fn key; Studio protects that access path.

## DKS, MPT or another advanced action cannot be assigned

Select a physical key other than Fn. Remove an existing SOCD or Rappy Snappy pair first. For Rappy Snappy, select a different physical partner with no conflicting advanced action. MPT thresholds must be strictly increasing; DKS thresholds must be ordered. Use the field validation messages before applying.

A successful register readback establishes stored configuration, not physical timing or game behavior. Report the observed physical result separately.

## A macro assignment is blocked

The SDK uses a shared macro staging buffer. Studio allows **one assigned sequence per profile** and prevents assigning a second macro over another binding. Remove the existing binding first.

Sequences must contain 2–64 balanced press/release events. Recording stops with Esc or Tab. Keep the exported `win60-macro-1` JSON file. Changing browser/storage or using another driver can leave the local original unavailable even when a keyboard binding is still present.

## A backup containing a macro cannot be exported

Studio cannot reconstruct arbitrary macro events from the device. A macro made in another driver needs its original sequence file; a binding header is not enough. Likewise, a locally cached header does not prove that an external tool has not overwritten the shared buffer. Preserve the original export rather than relying solely on browser storage.

## A backup is rejected

Check that the file is a Studio backup for the correct keyboard, is valid JSON and is no larger than 1 MB. The importer validates ranges, duplicate entries, advanced payloads and Fn access before restoring. Do not manually bypass that validation. A macro sequence export and a complete keyboard backup are different file formats.

## The interface opens in another language

The app uses your saved choice, or the first supported browser language. Change the workspace language menu to **English, Italiano, Русский, Español or 日本語**. If browser storage is disabled, choices may not survive reload. Diagnostic logs and unknown SDK/device details intentionally preserve their original text.

## A deployment stays queued

Check [the deployment workflow](https://github.com/PrimeBuild-pc/aula-win60he-tool/actions/workflows/pages.yml) and [GitHub Status](https://www.githubstatus.com/). A GitHub Actions/Pages incident can delay publication even after tests pass and the artifact is uploaded. Waiting for GitHub is different from a failed test or an environment approval request. Do not assume a deployment succeeded until its conclusion and the served page have been checked.

## What to include in a bug report

Provide the exact keyboard name, USB IDs, browser/OS, firmware/protocol if available, app version, steps, expected result and actual physical result. Include relevant diagnostic lines after reviewing them for personal data. Explain whether the issue occurs in the official driver too, if you have already tested that. Avoid attaching firmware binaries or full browser-storage exports.
